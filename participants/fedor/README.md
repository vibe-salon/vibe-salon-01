# Фёдор Холькин

## С чем пришёл

Kit для Google Sheets для дашбордов и визуального слоя, перенос своих лучших практик работы в таблицах в AI.

## Что получилось

**sheet-dash-kit**, новый проект (приватная репа): методичка по сборке дашбордов в Google Sheets и темы оформления. За основу взяты мои дашборды за несколько лет. Это следующий шаг после gas-kit, моего CLI поверх Apps Script. Код CLI `sdash` будет потом.

Что в ките:

- **Слои листа.** Лист дашборда разобран на шесть слоёв: фильтры, данные, таблицы, графики, статические параметры, тексты. У каждого слоя свои правила и свой файл.
- **Соглашения**, которые раньше жили только у меня в голове:
  - фильтры делаются ячейками с валидацией, без формул;
  - расчёты через QUERY и array-формулы, имена и формат колонок через `label` и `format`;
  - одна главная витрина на календаре дат, производные запросы вправо с зазором;
  - ячейки с формулами заливаются оранжевым и фиолетовым, текст под графиками белый;
  - 1 график = 1 запрос;
  - без сводных таблиц и слайсеров.
- **Обязательные листы.** В каждой таблице есть `main` (дашборд, таблица открывается на нём), «Настройки» и «Метрики». На «Метриках» расписано, как считается каждая цифра, блоками по листам дашборда.
- **Порядок работы.** Сначала мокап в Excalidraw, потом лист «Метрики», потом сборка.
- **Рецепты.** 20 приёмов с готовыми формулами. Среди них итоговая строка под KPI-плитки, сравнение с прошлым периодом, pivot двойным QUERY и условное форматирование по служебным флагам из array-формул.
- **Сборка с нуля через Sheets API.** 10 шагов с телами запросов. Сценарий целиком прогнан на временной таблице.
- **Темы Pastel и Nord** на шрифте Verdana. Тема ставится через API и сама перекрашивает графики, условное форматирование и чередование строк.
- **Журнал решений:** что выбрали, что отвергли и чем за это платим.

Объём: 15 файлов, около 4 800 строк, 4 коммита.

Что выяснилось про Google Sheets API, проверено на временных таблицах:

- Свою тему можно поставить на файл, но только целиком (шрифт и 9 цветов). Сохранить её в галерею тем нельзя.
- Шрифт темы не переходит в уже созданные графики, его надо переписывать в каждом.
- Мультиселекта и стиля чипов в валидации через API нет, это ручной шаг.
- Слайсер только прячет строки, QUERY и SUBTOTAL его не учитывают. Поэтому фильтры у меня ячейками.
- Новая таблица из API создаётся с локалью en_US, и формулы с `;` в ней не работают, пока не поставишь ru_RU.

## Как работали

Модель: **Claude Opus 5.5** (`claude-opus-5-5`) в Claude Code, на ней же все агенты. Сессия шла около двух часов, с 14:38 до 16:40.

Основную работу делала команда агентов (Workflow) в два прогона. Таблицы агенты только читали.

1. **Разведка, 7 агентов параллельно.** Шесть агентов разобрали по одной таблице: пять моих дашбордов (продажи на маркетплейсе как эталон, демо, маркетинговая воронка, расходы на маркетинг, отзывы) и прототип план-факта из моего поста в канале. Пост агент достал из Telegram через Telethon. Седьмой агент проверял возможности Sheets API на своих временных таблицах и потом их удалил.
2. **Методичка, 7 агентов параллельно**, у каждого свой файл.
3. **Критик.** Дал 47 замечаний: где методичка искажает мои соглашения, где непроверенное подано как факт, где ошибки в формулах, чего не хватает для сборки с нуля.
4. **Мои решения по спорным местам**, четыре вопроса:
   - ряд KPI-плиток считается одним запросом;
   - заливка формул одна на все темы;
   - видимые таблицы выделяются в отдельный слой;
   - место плиток зависит от отчёта.
5. **Правка, 8 агентов параллельно.** Один из них дописал новый файл о сборке с нуля и прогнал его на временной таблице. Девятый агент потом сверил все файлы между собой.
6. **Ручные уточнения** после этого: мокап до сборки, лист «Метрики» с блоками по листам, лист дашборда всегда `main`.

Токены:

| | Агентов | Вывод | Вход без кеша | Чтение кеша | Запись в кеш | Всего |
|---|---|---|---|---|---|---|
| Основная сессия | 1 | 64 тыс. | 0,1 тыс. | 9,76 млн | 0,24 млн | 10,06 млн |
| Агенты | 28 запусков | 362 тыс. | 0,6 тыс. | 16,32 млн | 1,99 млн | 18,68 млн |
| **Итого** | | **426 тыс.** | | **26,08 млн** | **2,24 млн** | **28,74 млн** |

Как читать таблицу. Вывод это то, что модели написали сами: методичку, ответы, формулы. Это реальный объём работы. Чтение кеша это повторное чтение одного и того же контекста: модель не помнит разговор между шагами, и на каждом шаге ей заново отдаётся всё, что было раньше, а уже виденная часть берётся из кеша. Поэтому 28,7 млн не значит 28 млн токенов разного текста. Это сколько раз модели перечитали свой контекст, и чтение из кеша стоит заметно дешевле нового входа.

28 запусков агентов: 7 на разведку, 4 из них пришлось перезапустить, 7 писателей, критик, 8 на правку и 1 на сверку. Почти весь объём это чтение кеша: каждый агент получал целиком итоги разведки и мои соглашения.

Чему научился по ходу:

- **Параллелить надо и сборку, а не только сбор.** В первой версии методичку писал один агент после параллельной разведки, и я спросил, почему работает один. После перезапуска писали семь агентов.
- **Не останавливать прогон, не проверив журнал.** Я решил, что разведка закончилась, а в журнале были только записи о старте. Четыре агента оборвались и запустились заново.
- **Нужен критик.** Без него в методичку попало бы правило, которого у меня нет («два графика на один диапазон»), и выводы про интерфейс, которые никто не проверял.

## Что дальше

- CLI `sdash`:
  - `new` собирает демо-дашборд по сценарию из методички;
  - `theme` ставит Pastel или Nord;
  - `lint` проверяет соглашения: формулы в фильтрах, заливку, белый текст, сводные.
- Проверить в браузере то, что видели только по ответам API: календарь на датах, KPI-плитки в закреплённой зоне при прокрутке, на каком листе открывается таблица без `#gid`.
- Собрать по киту первый боевой дашборд, начиная с мокапа в Excalidraw.
