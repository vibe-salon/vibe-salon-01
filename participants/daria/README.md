# Дарья Р.

## С чем пришла

Систематизация своих рабочих процессов, подход к ведению дел с AI.

Конкретный кусок на салон — личные финансы. Данные за несколько месяцев разъехались: Google-таблица перестала обновляться, актуальные цифры жили только в заметках Obsidian, а планов автоматизации было три, и все разные (Python-бот, n8n, бот с Claude API). Хотелось сначала навести порядок, а потом сделать так, чтобы трату можно было записать за пять секунд с телефона.

## Что получилось

**1. Порядок в финансовой папке Obsidian.**

- Собрала всё, что было по финансам: заметки, daily, планы ботов, Google-таблицу и Диск, память Claude.
- Разделила роли: **Google-таблица — база данных**, туда пишутся все операции, как в ДДС на работе (кофе, такси, аренда, кредиты, подушка). **Obsidian — сводки, решения, стратегия и документация.**
- Папку разложила на постоянные файлы и подпапки `Поступления/`, `Архив/`, `Автоматизация/`. Ни одна заметка не переписана: файлы только перемещены, а новые факты дописаны с датой. Проверено diff'ом с резервной копией: 0 удалённых строк, все ссылки между заметками живы.

**2. Telegram-бот для учёта денег на Google Apps Script.** Сервер и ИИ ему не нужны.

- **Команда = категория.** Нажимаю «☕ Кофе», бот спрашивает сумму, пишу `450`, и в таблице появляется строка: дата, расход, категория, сумма.
- **28 категорий** в листе «Справочник»: расходы, поступления, подушка. Новая категория — это новая строка в таблице плюс `/sync` в боте, код трогать не надо.
- **Ввод суммы по-человечески:** `450`, `1 500`, `30к`, `450 раф на овсяном` (текст уходит в комментарий), `10.10 450`, `вчера 450`. Если непонятно или дата в будущем, бот переспрашивает и ничего не пишет.
- **Реакции на сообщение:** 👌 расход, 🔥 поступление, 🏆 в подушку, 🤔 не поняла.
- **Команды** `/today`, `/month` (итоги), `/undo` (отмена статусом, строка не удаляется), `/cancel`.
- **«Сводка»** по типам и категориям за месяц считается формулами сама.
- **Защита:** бот отвечает только моему чату, секретный ключ в URL webhook, защита от дублей по `update_id`.
- **Диагностика** `…/exec?diag=1` показывает, на каком шаге застряло сообщение, без токенов и ключей.

Объём: 9 файлов кода (около 600 строк), README, 5 версий за день. Код в приватном репозитории.

**Что выяснилось про Apps Script + Telegram (проверено вживую):**

- Если `doPost` отвечает через `ContentService`, Google отдаёт **302**, Telegram считает это ошибкой и **застревает на первом сообщении**, а новые копятся в очереди. Помогает `HtmlService.createHtmlOutput()` — он отдаёт код 200.
- `clasp create --parentId` в clasp 3 **не привязывает** скрипт к существующей таблице, а молча создаёт новую. Пришлось сделать проект самостоятельным и открывать таблицу по ID.
- Таблица в локали ru_RU: формула, записанная из скрипта с запятыми, даёт `#ERROR!`, нужна `;`.
- Часовой пояс таблицы оказался GMT, а не Москва: московская полночь превращалась во вчерашний день. Решение — писать даты серийным числом по Москве.

## Как работали

Модель: **Claude Opus 5.5** (`claude-opus-5-5`) в Claude Code, одна сессия без агентов. Около 1 ч 45 мин, с 15:46 до 17:30.

1. **Разведка.** Claude прошёлся по папкам, заметкам и таблице через Sheets/Drive API и собрал картину: что есть, где расходится, что устарело.
2. **Мои решения.** Три вопроса: что пишем в базу (всё, как ДДС), чем разбирать сообщения, где живёт бот. По ходу я сменила архитектуру: вместо Python на сервере и Claude API — Apps Script + clasp, команда на каждую категорию, кнопки.
3. **План в plan mode**, потом наведение порядка: резервная копия, перемещения, точечные дописки, проверка diff'ом.
4. **Код** на Apps Script, разбор суммы проверен в Node на 20 вариантах ввода, `clasp push` / `clasp deploy`.
5. **Запуск и отладка.** Я вписала токен и запустила функции настройки в редакторе. Claude проверял результат через API: снимки хэшей старых листов до и после (не изменились), содержимое новых листов, диагностику бота. Нашли и починили три бага: даты, формулы и 302.
6. **Документация:** README в репозитории бота, заметка-журнал в Obsidian, коммиты.

Инструменты: Claude Code, Google Apps Script, clasp, Telegram Bot API, Google Sheets и Drive REST API, Node.js, git, Obsidian.

Токены:

| | Агентов | Вывод | Вход без кеша | Чтение кеша | Запись в кеш | Всего |
|---|---|---|---|---|---|---|
| Основная сессия | — | 93 тыс. | 0,2 тыс. | 14,24 млн | 0,20 млн | 14,53 млн |

Вывод — то, что модель написала сама: код, заметки, ответы. Чтение кеша — повторное чтение того же контекста на каждом шаге, оно дешевле нового входа.

**Чему научилась по ходу:**

- **Сначала правило, потом работа.** Я сразу сказала: «ничего не удаляй и не переписывай, сверяйся с исходниками». После этого каждое изменение шло с резервной копией и проверкой diff'ом, а любые спорные правки Claude сначала показывал мне.
- **Архитектуру можно менять на ходу.** План с сервером и Claude API за минуту превратился в Apps Script без сервера — проще и бесплатно.
- **Диагностика окупается сразу.** Без `?diag=1` мы бы гадали, почему бот молчит. С ней за пару минут увидели застрявшую очередь Telegram и её причину.
